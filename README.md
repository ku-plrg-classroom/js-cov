# JavaScript Coverage Profiler

This is a homework assignment, and the goal of this assignment is to create a
simple **JavaScript coverage profiler** that measures the function, statement,
and branch coverage of a given JavaScript code.

It utilizes the [`acorn`](https://github.com/acornjs/acorn) library to parse the
JavaScript code and the [`astring`](https://github.com/davidbonnet/astring)
library to generate the instrumented JavaScript code.

We recommend you to use [`acorn-walk`](https://www.npmjs.com/package/acorn-walk)
to traverse the AST (Abstract Syntax Tree) of the JavaScript code generated by
the `acorn` library.

Please refer to the following documents for more information:
* [Type Definitions for `acorn`](https://github.com/acornjs/acorn/blob/master/acorn/src/acorn.d.ts)
* [Documentation for `acorn-walk` documentation](https://github.com/acornjs/acorn/tree/master/acorn-walk)
* [AST Explorer](https://astexplorer.net/)

## Implementation

**Please implement the missing parts** (denoted by `todo()` functions) in the
[`src/coverage.ts`](./src/coverage.ts) file, which contains the `Coverage`
class, which is responsible for calculating the function, statement, and branch
coverage of a given JavaScript code. The parsing (`acorn`), code generation
(`astring`), execution, and reporting are given, and so is `walkStmts`, which
instruments a list of statements -- read it first, it is the pattern every
visitor follows. You implement the **visitors** of the AST.

The **goal** of this project to **instrument** the given JavaScript code and
measure the function, statement, and branch coverage of the given JavaScript
code by considering the following elements:


### Function Coverage

1. `Function`

   > For example,
   > ```javascript
   > function add(a, b) { ... }
   > ```
   > should be instrumented as
   > ```javascript
   > function add(a, b) { __cov__.func.add(0); ... }
   > ```


### Statement Coverage:

1. `Statement` but not `Declaration`

   > For example,
   > ```javascript
   > return a + b;
   > ```
   > should be instrumented as
   > ```javascript
   > __cov__.stmt.add(0);
   > return a + b;
   > ```

1. `Expression` in the `body` field of the `Function`

   > For example,
   > ```javascript
   > (a, b) => a + b;
   > ```
   > should be instrumented as
   > ```javascript
   > (a, b) => { __cov__.stmt.add(0); return a + b; };
   > ```

1. `Expression` in the `init` field of the `VariableDeclarator`

   > For example,
   > ```javascript
   > let a = 1;
   > ```
   > should be instrumented as
   > ```javascript
   > let a = (__cov__.stmt.add(0), 1);
   > ```

1. `Expression` in the `right` field of the `AssignmentPattern`

   > For example,
   > ```javascript
   > var { x = 1, y, z } = ...;
   > ```
   > should be instrumented as
   > ```javascript
   > var { x = (__cov__.stmt.add(0), 1), y, z } = ...;
   > ```


### Branch Coverage

1. `IfStatement`

   > For example,
   > ```javascript
   > if (a > b) return a;
   > ```
   > has no `else`, so the else branch is recorded with an **empty range** at
   > the end of the `if` statement, and the single-statement body is treated as
   > a block:
   > ```javascript
   > if (a > b) { __cov__.branch.add(0); __cov__.stmt.add(1); return a; }
   > else { __cov__.branch.add(1); }
   > ```

1. `IfStatement` with an `else`

   > For example,
   > ```javascript
   > if (a > b) { ... }
   > else { ... }
   > ```
   > should be instrumented as
   > ```javascript
   > if (a > b) { __cov__.branch.add(0); ... }
   > else { __cov__.branch.add(1); ... }
   > ```

1. `ConditionalExpression`

   > For example,
   > ```javascript
   > a > b ? c : d
   > ```
   > should be instrumented as
   > ```javascript
   > a > b ? (__cov__.branch.add(0), c) : (__cov__.branch.add(1), d)
   > ```

1. `SwitchCase` in `SwitchStatement`

   > For example,
   > ```javascript
   > switch (a) {
   >   case 1: ...
   >   case 2: ...
   >   default: ...
   > }
   > ```
   > should be instrumented as
   > ```javascript
   > switch (a) {
   >   case 1: __cov__.branch.add(0); ...
   >   case 2: __cov__.branch.add(1); ...
   >   default: __cov__.branch.add(2); ...
   > }
   > ```

1. **Each Clause** in `LogicalExpression`

   > For example,
   > ```javascript
   > (
   >    (b || b) ||
   >    (b && b) &&
   >    (b ?? b)
   > ) ?? !b
   > ```
   > should be instrumented as
   > ```javascript
   > (
   >   ((__cov__.branch.add(0), b) || (__cov__.branch.add(1), b)) ||
   >   (((__cov__.branch.add(2), b) && (__cov__.branch.add(3), b)) &&
   >   ((__cov__.branch.add(4), b) ?? (__cov__.branch.add(5), b)))
   > ) ?? (__cov__.branch.add(6), !b);
   > ```


### Rules Pinned Down by the Examples

The examples in the [`example`](./example) directory fix the details that the
rules above leave open. In particular:

* A statement gets an id when it appears in a **statement list**: a block, a
  function body, or the consequent of a `switch` case. A single-statement body
  of `if`, `else`, or a loop is treated as a one-statement block, so it gets an
  id too. Empty statements (`;`) and empty blocks (`{ }`) are statements.
* `else if (...) ...`: the nested `if` is the body of the `else`, so it gets a
  **branch** id (as the alternate) **and** a **statement** id.
* `label: stmt`: both the labeled statement and its body are statements, so both
  get ids. Keep the label directly on the loop -- `continue label;` is a syntax
  error if `label` ends up on a block.
* `switch`: the marker is the first statement of each case's consequent, so
  **falling through** into a case covers it, and an empty `case 1:` is a branch
  of its own.
* Declarations (`function`, `class`, `let`/`const`/`var`) are not statements,
  but their initializers are (see above). Class field initializers are not.
* Logical assignments (`||=`, `&&=`, `??=`) and optional chaining (`?.`) are
  **not** branches: only `LogicalExpression`, `ConditionalExpression`,
  `IfStatement`, and `SwitchCase` are.

Each test requirement is reported with a **source range** (`line:col-line:col`):

| Kind      | Test requirement              | Range                                   |
| --------- | ----------------------------- | --------------------------------------- |
| `func`    | a function                    | the whole function                      |
| `stmt`    | a statement                   | the statement                           |
| `stmt`    | an initializer / default      | the expression                          |
| `stmt`    | an arrow function's body      | the body expression                     |
| `branch`  | `if` then / else              | the consequent / the alternate          |
| `branch`  | `if` without `else`           | the empty range at the end of the `if`  |
| `branch`  | `? :` then / else             | the consequent / the alternate          |
| `branch`  | `case` / `default`            | the whole `SwitchCase`                  |
| `branch`  | a clause of `&&` `\|\|` `??`   | the clause                              |

**The numbering of ids does not matter.** The tests compare the source ranges of
the test requirements and of the covered ones, so any traversal order that
produces the same ranges is accepted.
